# Формат: одно разрешение в строке, комментарии после #.

# Весь обмен с сервером: Retrofit/OkHttp, авторизация, синхронизация клиентов и

android.permission.INTERNET

android.permission.RECORD_AUDIO

# ── Приходит из библиотеки при слиянии манифестов ─────────────────────────
#
# Это разрешение не писал никто из нас: его вписывает androidx.core, и увидеть
# его можно только в ГОТОВОМ пакете — в шаблоне манифеста приложения его нет.
# Ровно ради таких случаев сторож и проверяет пакет, а не шаблон.
#
# Что оно делает: это СОБСТВЕННОЕ разрешение приложения с уровнем защиты
# signature. Им androidx.core закрывает приёмники, которые приложение
# регистрирует на ходу (ContextCompat.registerReceiver с RECEIVER_NOT_EXPORTED),
# чтобы до них не дотянулись чужие приложения. Человеку при установке оно не
# показывается и ничего у него не просит: выдать его может только приложение,
# подписанное тем же ключом, то есть само приложение.
#
# Измерено, а не предположено: разбором двоичного манифеста из настоящего
# пакета релиза android-v1.0.6-b251.
ru.cmpas.app.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION  # ИЗ БИБЛИОТЕКИ

# Пришло с SDK ВК (com.vk.id) вместе с нативным входом. Разрешение
# «посмотреть, есть ли сеть»: даёт ответ на вопрос, подключён ли телефон и
# каким способом — Wi-Fi или мобильной связью. Не даёт ни списка сетей, ни
# их имён, ни местоположения; человеку при установке не показывается, потому
# что относится к обычным, а не опасным.
#
# Зачем оно SDK: отличить «человек закрыл окно входа» от «сети нет» — без
# этого второе показывалось бы как отказ провайдера.
#
# Измерено в готовом пакете сборки 1.3.5, а не взято из документации.
android.permission.ACCESS_NETWORK_STATE  # ИЗ БИБЛИОТЕКИ (SDK ВК)
