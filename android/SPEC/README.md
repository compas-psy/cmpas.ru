# КОМПАС · Android — полное ТЗ на приведение к дизайну 1:1

> **Кому:** агенту-разработчику (Claude Code), работающему в реальном
> Android-репозитории КОМПАС.
> **Что сделать:** за один проход привести Android-приложение к
> HTML-прототипу **пиксель-в-пиксель** и подключить **каждое**
> взаимодействие (каждую кнопку, вкладку, лист, поле).
> **Стек:** Kotlin · Jetpack Compose · Material3 · Hilt · Navigation-Compose.

---

## 0. Источник истины (single source of truth)

Дизайн задаётся **HTML-прототипом в корне проекта**. Это не «вдохновение», а
эталон — все размеры, цвета, отступы, копирайт и поведение берутся **оттуда**:

| Файл прототипа | Что описывает |
|---|---|
| `index.html` | CSS-токены, glass-рецепты, типошкала, анимации |
| `compas-ui.jsx` | палитра `C`, иконки, моки данных, **Dock + FAB**, Avatar, статусы |
| `compas-screens.jsx` | экраны Today, Calendar, Clients, ClientDetail, SessionDetail, PushScreen |
| `compas-comms.jsx` | мессенджер, листы (Написать / Пригласить / Документ), напоминания |
| `compas-notes.jsx` | редактор заметки (3 режима) |
| `compas-app.jsx` | корневая навигация, FAB-лист, экран Профиль/Настройки |

**Правило:** если данные в этом ТЗ и в прототипе разойдутся — прав прототип.
Открывай `compas-*.jsx` и сверяй значения напрямую.

Точные числовые значения продублированы в `SPEC/01-design-system.md`, чтобы их
не приходилось вычислять из CSS.

## 1. Почему сейчас «по факту кошмар» — что чинить в первую очередь

Скриншоты текущей сборки показывают 3 класса расхождений. Их чинить
обязательно — это критерии приёмки, а не пожелания:

### Баг A — карточка «Следующая сессия» (экран Сегодня)
Имя клиента переносится на 2 строки и **наезжает** на бейдж времени
«14:00–14:50 · Онлайн». Причина: имя и бейдж времени положены в один ряд.
**Как в прототипе** (`TodayScreen`, hero `glass-tint`): строгая вертикальная
структура в 3 яруса:
1. верхний ряд: надпись-eyebrow «СЛЕДУЮЩАЯ СЕССИЯ» слева + пилюля «через N ч/мин» справа;
2. ряд: аватар + имя (**одна строка, `maxLines=1`, ellipsis**) и под именем — мета `время · длительность · формат`;
3. ряд кнопок: белая «Подключиться» (flex) + квадратная иконка «заметка».
Бейдж времени **никогда** не стоит в одном ряду с именем.

### Баг B — нижнее меню (Dock)
Сейчас это обычный `NavigationBar`: не стеклянный, подписи спрятаны/наезжают на
обводку выделенной иконки.
**Как в прототипе** (`Dock`, `DockBtn`, класс `.glass-dock`): **плавающий
стеклянный док-«таблетка»**, не приклеен к краю (отступ снизу 14 dp,
скруг­ление 30 dp), с **центральным FAB**. Активная вкладка — мягкая пилюля-
подложка _за_ иконкой (никаких обводок поверх текста). Подпись всегда видна под
иконкой. Полная спека дока — в `01-design-system.md` §4.

### Баг C — Календарь и Клиенты «не так красиво»
Сейчас плоский Material. Нужно: стеклянные карточки (`GlassCard`, радиус 22),
сетка месяца в `glass-strong`-карточке с градиентной выделенной датой и
точками-индикаторами загрузки дня; строки клиентов — стеклянные с аватаром-
«сквиркл», тегом-пилюлей и строкой «ближайшая сессия». Точные раскладки —
в `02-screens.md`.

## 2. Порядок работы (делай строго так)

1. **Фундамент темы.** Создай/обнови `presentation/theme/` — палитра `Compas*`,
   типошкала, радиусы, и **glass-утилиты** (см. §01). Без этого слоя ничего не
   будет похоже.
2. **Переиспользуемые компоненты** (`presentation/components/`): `GlassCard`,
   `GlassTintCard`, `GlassDock` + `CenterFab`, `CompasBottomSheet`,
   `PrimaryButton`, `GhostButton`, `CompasSegmented`, `Avatar`, `StatusPill`,
   `ChannelChip`, `IconButtonGlass`, `Ambient` (фоновое свечение).
3. **Каркас навигации.** `MainActivity` → `CompasApp()`: `Scaffold` без
   стандартного `bottomBar`; собственный `GlassDock` поверх контента; 4 таба +
   FAB-лист; стек push-экранов через Navigation-Compose.
4. **Экраны по списку** (`02-screens.md`): Today → Calendar → Clients →
   ClientDetail → SessionDetail → NoteEditor → Profile. После каждого — сверка
   со скриншотом прототипа.
5. **Все листы и взаимодействия** (`03-interactions.md`): пройди чек-лист
   построчно, ни одна кнопка не должна быть «пустышкой».
6. **Самопроверка** по DoD ниже.

## 3. Глобальные правила реализации

- **Никакого хардкода цветов** мимо темы. Только `Compas*`-токены /
  `MaterialTheme.colorScheme`.
- **Шрифт — Geist** (вес 400/500/600/700/800). Подключить как ресурс-шрифт;
  если в репозитории его нет — добавить в `res/font/` и завести `FontFamily`.
- **Стекло (`backdrop blur`).** В Compose настоящего `backdrop-filter` нет.
  Базовый приём — полупрозрачная белая поверхность + тонкая светлая граница +
  мягкая тень над фоновым градиентом (значения в §01). **Рекомендуется**
  подключить библиотеку **Haze** (`dev.chrisbanes.haze`) для настоящего
  размытия фона у дока/листов/карточек — это даёт эффект 1:1. Если добавлять
  зависимость нельзя — оставляем полупрозрачный вариант (выглядит как на
  скриншотах прототипа).
- **Скругления — крупные.** Карточки 22 dp, листы сверху 30 dp, кнопки 14–16 dp,
  FAB 22 dp. Никаких острых углов.
- **Press-эффект.** На всех нажимаемых элементах лёгкое `scale(0.975)` на
  нажатии (как `.press` в прототипе) — через `Modifier.pointerInput` +
  `animateFloatAsState`, либо общий `Modifier.pressScale()`.
- **Анимации входа push-экрана** — slide-in справа (`slideIn`), листов снизу —
  `slideUp`; уважать `prefers-reduced-motion` (в Android — проверка
  `Settings.Global.ANIMATOR_DURATION_SCALE` или просто без обязательной
  анимации в контенте).
- **Тексты — точь-в-точь из прототипа** (включая «Добрый день, Никита»,
  «Следующая сессия», «Уходят автоматически» и т. д.).
- Существующие файлы (`SessionDetailScreen.kt`, `ClientDetailScreen.kt`,
  `NotesScreen.kt`, `PostSessionNoteScreen.kt`, `SettingsScreen.kt`,
  `QuickActionScreen.kt`, `ExpandableActionMenu.kt`, `Models.kt`) —
  **переписывай под прототип**, не пытайся сохранить старую раскладку.

## 4. Definition of Done (критерии приёмки)

Готово, когда **всё** выполнено:

**Визуал**
- [ ] Док — плавающая стеклянная таблетка с центральным FAB; подписи видны,
      активный таб — пилюля-подложка, обводки не наезжают на текст. (Баг B)
- [ ] Hero-карточка «Следующая сессия»: имя в одну строку с ellipsis, бейдж
      времени не в ряду с именем, ничего не наезжает. (Баг A)
- [ ] Календарь и Клиенты — стеклянные карточки, выделенная дата с градиентом и
      точками загрузки, строки клиентов с аватаром-сквирклом и тегом. (Баг C)
- [ ] Все карточки — стекло с крупным скруглением; фон экрана — тёплый `bg`
      `#FAF8F5` с фоновым свечением (`Ambient`).
- [ ] Палитра, типошкала, радиусы совпадают с §01 (точечная сверка 5–6 экранов
      со скриншотами прототипа).

**Функционал (каждое взаимодействие, см. `03-interactions.md`)**
- [ ] 4 таба переключаются; FAB открывает лист «Быстрое действие».
- [ ] Today: тап по hero → SessionDetail; «Подключиться»/иконка-заметка
      работают; строки расписания → SessionDetail; «Весь день» активна.
- [ ] Calendar: сегмент День/Неделя/Месяц/Список; выбор даты обновляет агенду;
      ‹ › листают месяц; «Записать» открывает лист; строка → SessionDetail.
- [ ] Clients: сегмент Активные/Все/Архив; поиск фильтрует; строка → ClientDetail;
      «+» открывает создание.
- [ ] ClientDetail: 4 вкладки (Обзор/Записи/Заметки/Документы); «Написать»/
      «Пригласить»; баннер согласия → лист документа; «Записать сессию»,
      иконка-заметка; строки сессий/заметок/документов кликабельны.
- [ ] SessionDetail: заметки **выше** напоминаний; карточка напоминаний
      **свёрнута**, по тапу разворачивается; «Подключиться», «Написать»,
      «Заметка», «Перенести», «Отменить» — все живые.
- [ ] NoteEditor: 3 режима (Кратко/По блокам/Голосом); поля редактируются; теги
      добавляются/удаляются; «Сохранить»/«Позже».
- [ ] Листы: Написать (с шаблонами и веткой «вручную» для непривязанных),
      Пригласить (выбор Telegram/MAX + ссылка), Документ (выбор шаблона + ack),
      экран «Отправлено/Готово к отправке».
- [ ] Profile: тумблеры автонастроек переключаются; блок оплаты, мессенджеры,
      строки настроек на месте.

**Качество**
- [ ] Проект собирается (`./gradlew assembleDebug`) без ошибок и варнингов
      компилятора.
- [ ] Нет «мёртвых» кнопок: каждый `onClick` делает осмысленное действие
      (навигация, лист, тумблер, фильтр) либо явно помечен `// TODO API` с
      рабочей заглушкой-навигацией, как в прототипе.
