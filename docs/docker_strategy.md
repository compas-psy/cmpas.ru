# Docker Migration Strategy

## 1. Концептуальные отличия

### Текущий метод (SSH + Git Pull)
- **Как работает**: Мы подключаемся к серверу, скачиваем изменения (`git pull`), запускаем сборку (`npm run build`) прямо на сервере и перезапускаем процесс (`pm2 restart`).
- **Плюсы**: Простота настройки.
- **Минусы**:
  - Нагрузка на сервер при сборке (build занимает процессорное время).
  - Среда на сервере мутирует (со временем накапливается мусор).
  - Риск, что `npm install` сломается из-за версий Node.js.

### Новый метод (Docker + GitHub Actions)
- **Как работает**: GitHub собирает "образ" (коробку) с уже готовым приложением. На сервер отправляется только готовая коробка.
- **Плюсы**:
  - **Изоляция**: Работает одинаково везде.
  - **Безопасность**: Серверу не нужно строить приложение, он его только запускает.
  - **Откат**: Легко вернуться на старую версию (просто запустить старую коробку).

## 2. Про Базу Данных и "Перезатирание"
Контейнеры Docker **эфемерны** — это значит, что при перезапуске всё, что было внутри них (файлы), исчезает.
**НО** это решается механизмом **Volumes** (Тома).

Мы скажем Docker'у:
> "Храни данные приложения (базу данных, загруженные картинки) НЕ внутри контейнера, а в специальной папке на самом сервере".

```yaml
volumes:
  - ./db_data:/var/lib/postgresql/data  # Для базы данных
  - ./uploads:/app/public/uploads       # Для картинок
```
При обновлении мы удаляем контейнер с кодом, но **папка на сервере остается нетронутой**. Новый контейнер подключается к той же папке.

## 3. План реализации

1.  **Dockerfile**: Инструкция, как упаковать Next.js приложение.
2.  **docker-compose.yml**: Файл для управления "оркестром" (Приложение + в будущем База Данных).
3.  **GitHub Action**: Скрипт, который:
    - Собирает образ (можно собирать на GitHub и грузить в Registry, либо собирать на сервере).
    - *Для упрощения и экономии (GitHub Registry платный/лимитированный для приватных репо) мы будем пока собирать на сервере, но внутри Docker.*

### Workflow "Safe Deploy"
1.  **Trigger**: Push in `main` OR Button Press (workflow_dispatch).
2.  **Action**:
    - SSH на сервер.
    - `git pull` (обновляем рецепты, а не код).
    - `docker compose build` (собираем новый контейнер).
    - `docker compose up -d` (перезапускаем без простоя).
