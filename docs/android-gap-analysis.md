# Android-приложение: сравнение с веб-версией и план доработок

Дата анализа: 2026-06-10. Источники: `android/` (Kotlin + Jetpack Compose), `src/app/api/mobile/**`, веб-кабинет `src/app/diary/**`.

---

## 1. Текущее состояние

### Архитектура
- **Web (desktop + mobile web)** — полнофункциональный кабинет `/diary`: клиенты, сессии, расписание, умные заметки, документы/согласия, оплата, интеграции, уведомления, рассылки через ботов.
- **Android** — нативное приложение (Kotlin 2.1, Compose, Hilt, Retrofit, offline-first через локальные стораджи), работает через выделенный REST-слой `https://cmpas.ru/api/mobile/`.

### Что в приложении сломано (UI есть, сервера нет)
| Возможность | Проблема |
|---|---|
| **Перенос сессии** | Приложение шлёт `date`/`startTime` в `PATCH /sessions/{id}`, но сервер обрабатывает только `status` и `notes` → перенос молча игнорируется (`src/app/api/mobile/sessions/[id]/route.ts`) |
| **Отмена сессии** | Приложение вызывает `DELETE /sessions/{id}` — эндпоинта нет → ошибка |
| **Push-уведомления** | `POST /fcm/register` объявлен в `CompasApi.kt`, эндпоинта нет; Firebase Messaging в приложении вообще не подключён |
| **Запись клиента (Booking/MyBookings)** | Экраны вызывают `GET /calendar/slots` и `POST /calendar/book` — эндпоинтов нет |
| **Блокировки расписания** | Хранятся только локально (`LocalScheduleBlockStore`), на сервер не уходят → веб их не видит |
| **Деталь сессии** | Нет `GET /sessions/{id}` — приложение грузит ВСЕ сессии и ищет по id на клиенте |

### Чего нет в Android по сравнению с вебом (полный список)
- Редактирование / архивация / удаление клиента (в mobile API нет PATCH/DELETE клиентов)
- Анкета клиента (questionnaire), таймлайн, документы клиента
- Умные заметки (структурированные блоки: запрос, наблюдение, интервенция, динамика, ДЗ, следующий шаг), приватные заметки, резюме для клиента
- Перенос с подбором свободных слотов (`getAvailableTimesForReschedule`)
- Управление расписанием: слоты доступности, правила расписания, блокировки времени
- Отправка сообщений клиенту (вручную и автоматически), история доставки
- Документы и согласия (библиотека, автоотправка, отслеживание подтверждений)
- Настройки оплаты (текст / ссылка / QR), платёжные инструкции в сообщениях
- Шаблоны уведомлений (напоминания за 24ч/1ч, отмена, пост-сессионный чек)
- Интеграции: Google/Yandex календари, статус Telegram/MAX
- Ссылка самозаписи (поделиться booking-ссылкой)
- Панель «Требует внимания» (`attentionItems` в `/api/mobile/dashboard` всегда пустой)
- Импорт клиентов (списком, из календаря)
- Биллинг/триал, помощь, аналитика

## 2. Приоритеты пользователя (из практики)

1. **Быстро искать клиентов** — поиск уже работает (web и Android), доработка ниже минимальная.
2. **Управлять временем сессий: переносить, подтверждать** — в Android сломано (см. выше), на вебе есть полностью.
3. **Принудительно отправлять клиенту сообщение** вида: «Привет, {имя}! Напоминаю про встречу завтра, {дата} в {время}. Всё в силе? Оплата до встречи {сумма} руб по ссылке (+QR). Ссылка на онлайн-сессию: {telemost}» — **в том числе по расписанию**.
3. **Достучаться до клиента, который никогда не контактировал с сервисом** (занесён вручную с телефоном).

### Важное ограничение платформ (п. 4)
Ни Telegram Bot API, ни MAX Bot API **не позволяют боту написать первым** человеку, который не запускал бота, и не позволяют найти chatId по номеру телефона. Это ограничение платформ, обойти его сервером нельзя. Решения:

- **Инвайт-ссылка с автопривязкой**: deep-link `t.me/<bot>?start=c_<token>` (и аналог для MAX), где токен привязан к `clientId`. Клиент кликает один раз → бот сразу линкует его к карточке клиента, без ручного выбора психолога. Психолог отправляет ссылку любым способом (своим Telegram, WhatsApp, SMS).
- **Ручная отправка как первоклассный сценарий**: сервис генерирует готовый текст (как на скриншоте: напоминание + оплата + telemost + инвайт-ссылка), а психолог отправляет его «от себя»:
  - Android: системный share-sheet + прямые интенты `https://wa.me/+7…?text=…`, `sms:+7…?body=…`, `tg://` — телефон клиента уже есть в карточке;
  - Web: кнопка «Скопировать сообщение» (паттерн уже есть — `buildClientManualDocumentMessage`).
  - Факт ручной отправки фиксируется в истории доставки со статусом `manual`.
- **Для отложенной отправки непривязанным**: автоматически отправить нельзя → в назначенное время психолог получает push «Пора отправить напоминание Максиму» с кнопкой, открывающей share-sheet с готовым текстом (1 тап).
- Опционально (позже): SMS-шлюз / WhatsApp Business API — платно, Горизонт 2.

## 4. Сводка по трём вопросам пользователя

1. **Поиск клиентов** — уже работает в обеих версиях; в Android поиск дополнительно ищет по локальным заметкам. Доработок не требуется (опционально: вывод канала связи в результатах — п. 1.6).
2. **Перенос/подтверждение сессий** — на вебе есть полностью; в Android UI частично есть, но сервер игнорирует перенос и не умеет отмену → P0.1–0.7.
3. **«Принудительное» сообщение со скриншота** — все кирпичи уже есть на сервере (шаблоны напоминаний, платёжная ссылка/QR, ссылка на видеовстречу), нет только кнопки «отправить сейчас», отложенной отправки и мобильного UI → P1.1–1.5.
4. **Клиент без контакта с сервисом** — ограничение Telegram/MAX: бот не может написать первым и не находит по телефону. Решение: инвайт-ссылка с автопривязкой + ручная отправка через share-sheet/WhatsApp/SMS как полноценный сценарий с историей + push-напоминание психологу для «отложенных» сообщений → P1.3–1.5.
