# Управленческая панель СИМПАС — заметки к реализации

Адрес: `https://cmpas.ru/admin/panel/morning`. Экраны живут под `/admin/panel/*`,
существующая админка по `/admin` осталась на месте.

## Как устроено

```
src/lib/panel/
  types.ts        контракт PanelBlock: ok / loading / no_data / stale / broken
  thresholds.ts   все пороги; магических чисел в компонентах нет
  palette.ts      шесть слотов палитры + матрица различимости (см. palette-report.md)
  redact.ts       вычистка свободного текста перед показом (§8)
  topics.ts       закрытый словарь тем обращений
  cache.ts        unstable_cache, TTL 5 минут, тег на экран
  auth.ts         requirePanelAdmin() для route handlers
  queries/        по файлу на экран, каждый запрос возвращает PanelBlock
  build/          сборщики экранов: имя блока → PanelBlock
src/components/panel/   компоненты, все цвета через var(--…)
src/app/admin/panel/    восемь экранов + токен-слой panel.css
src/app/api/admin/panel/  GET — экран, POST — сброс кеша этого экрана
```

## Три правила, которые нельзя нарушать

1. **`no_data` не рисуется нулём.** Ноль — это измеренный ноль. Отсутствие данных —
   пунктирная рамка, слова «данных нет» и причина. Разницу проверяет
   `__tests__/states.test.tsx`.
2. **`reason` обязателен** для всех состояний, кроме `ok`. Пустая причина роняет
   конструктор блока, а не проходит молча.
3. **`source` печатается на экране** моноширинным под блоком. Это способ проверить
   число, а не украшение.

Плюс отдельно: **«не проверено» никогда не зелёное**, и **карточка «Резервные копии»
не может быть зелёной, пока `SystemConfig.backup_restore_drill_at` пуст** — оба
правила закреплены тестами.

## Авторизация

Единственная проверка роли — `src/app/admin/layout.tsx`. Панель её наследует.
Route handlers живут вне дерева layout'ов, поэтому вызывают ту же `auth()` через
`lib/panel/auth.ts` на каждом запросе. Второго механизма нет.

Чтобы панель не тащила за собой чужую боковую рельсу, chrome существующей админки
переехал в route group `src/app/admin/(chrome)/` — адреса не изменились, route group
на пути не влияет. В корневом `admin/layout.tsx` осталась только авторизация и
`robots: noindex`, которые наследуют оба поддерева.

## Ручные значения

Две величины панель не может измерить и получает от человека. Обе вводятся прямо в
том блоке, который их показывает — отдельного экрана под них нет намеренно (ТЗ §11:
«не добавлять экраны сверх восьми»).

| Что | Где вводится | Ключ в `SystemConfig` | Что даёт |
|---|---|---|---|
| Дата учебного восстановления копии | «Техника» → карточка «Резервные копии» (`/admin/panel/tech#backup`) | `backup_restore_drill_at` | пока пусто — карточка и лампа «Бэкап» не могут быть зелёными ни при каких обстоятельствах |
| Стоимость инфраструктуры, ₽/мес | «Деньги» → блок «Стоимость инфраструктуры» (`/admin/panel/money#cost`) | `infra_cost_rub` | пока пусто — блок в `no_data` с причиной «расходы никто не собирает» |

Обе формы пишут через server actions в `src/app/admin/panel/actions.ts`. Роль там
проверяется той же `auth()`: server action — такая же точка входа, как route handler,
и layout её не закрывает. `SystemConfig` — единственная таблица, куда панель пишет;
это закреплено тестом `__tests__/manual-values.test.ts`.

Правила ввода:

* дата восстановления — только прошедшая: отмечается проведённая проверка, не план;
* пустое поле даты снимает отметку, и карточка снова перестаёт быть зелёной;
* незаполненная статья расхода остаётся пустой, а не нулём — ноль означал бы
  «хранилище бесплатное», а не «сумму не вводили»;
* после сохранения кеш затронутых экранов сбрасывается сам, обновлять руками не нужно.

## Что честно не измеряется

Эти блоки реализованы в `no_data` с настоящей причиной. Это не задел на потом —
это текущее положение дел, и панель обязана показывать его как есть.

| Блок | Причина |
|---|---|
| Все блоки ЗАПИСОК | у ЗАПИСОК отдельный сервер, общего приёмника ещё нет |
| Все блоки МОМЕНТОВ | у МОМЕНТОВ нет сервера, события копятся на устройстве |
| Рассылка, «напоминания вовремя» | `ReminderOutbox` в схеме нет |
| «Кто заводит запись» | признака автора записи в `DiarySession` нет |
| Воронка записи на сессию | событий `booking_*` нет в реестре `analytics/schema/events.yaml` |
| Источники привлечения | utm лежит в `VisitorAnalytics` по отпечатку устройства и с аккаунтом не связан |
| Ответ 95-го процентиля | время ответа никто не замеряет |
| Хранилище ЗАПИСОК | чужая база |
| Причины оттока | опроса при отмене подписки нет |
| Стоимость инфраструктуры | пока не заполнен `infra_cost_rub` |

Счётчик «честных дыр» на экране «Качество данных» считает их на лету, а не хранит число.

## Пороги

Все в `src/lib/panel/thresholds.ts`. **Подтверждены владельцем 20.08.2026** — каждое
значение помечено отметкой `// подтверждено владельцем DD.MM` рядом с самим числом,
чтобы её нельзя было потерять при правке. Тест `__tests__/thresholds.test.ts` падает,
если у порога такой отметки нет.

Новый порог заводится в `UNCONFIRMED_THRESHOLDS`, пока его не согласовали: панель
такой порог применяет, но подписывает на экране «порог не подтверждён владельцем».
Сейчас список пуст.
