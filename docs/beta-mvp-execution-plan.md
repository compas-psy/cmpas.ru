# План реализации beta MVP Android

Основание: `docs/strategy.md`, `docs/cjm-beta.md`, PDF «CJM Карта Беты» и PDF «ТЗ Бета». Карта описывает полный целевой CJM беты, а ТЗ — конкретизированный исполняемый backlog. Поэтому реализация ведётся не как набор разрозненных багфиксов, а как закрытие 8 клиентских путей до состояния beta MVP.

## Принципы исполнения

1. P0 из ТЗ закрываются первыми, потому что они влияют на доверие, 152-ФЗ, целостность данных и отсутствие кнопок-обманок.
2. Каждый CJM из карты должен иметь либо рабочий путь в Android/web/MAX/Telegram/web-fallback, либо честный teaser `Скоро ✨` без имитации действия.
3. Старые `/api/mobile/*` остаются обратно совместимыми.
4. КОМПАС не принимает оплату: только инструкция специалиста и статус оплаты.
5. Дизайн-система не меняется: зелёная/золотая палитра, iOS-like glass-компоненты, бережные тексты.

## Порядок работ

### Этап 1 — юридическая чистота и безопасность

- SEC-1: отмена из клиентского miniapp только с `clientId + clientActionToken` и проверкой принадлежности сессии клиенту.
- LEGAL-1: убрать любые неявные акцепты, legal gate до onboarding, snapshot `source`, `documentType`, `documentVersion`, `acceptedAt`.
- DOC-1: клиентское согласие только через явную кнопку и чекбокс; открытие документа фиксирует только `openedAt`.

### Этап 2 — сердце мобильной беты

- CONNECT-1: реальная smart-ссылка `/connect/<token>`, MAX-first, QR/share/copy, live channel status.
- SCHED-1: любые блокировки времени из телефона пишутся на сервер в `DiaryBlock`; локальные блокировки — только кэш/миграционный fallback.
- NOTES-1: `structuredNotes` — единый источник правды между Android и web; `notes` остаётся legacy plain text.

### Этап 3 — ежедневный CJM психолога

- COMPLETE-1: автозавершение прошедших confirmed-сессий и мягкий нудж на заметку.
- PAY-1: реальный `paymentStatus`, видимый с Android и web.
- CANCEL-1: единая политика отмены N часов во всех каналах.
- NOTIF-1: персистентный центр уведомлений, read-state, FCM, тихие часы.

### Этап 4 — перенос практики и юридический журнал

- ONB-1: onboarding без потерь полей + документы + мессенджер + первый клиент.
- CONSENT-2/JOURNAL-1/DOCVER-1: список клиентов без согласия, журнал документов, CSV-экспорт, новая версия договора → массовая переотправка.
- IMPORT-1: импорт календаря с будущими сессиями, а не только именами.

### Этап 5 — честные будущие функции

- VOICE-1: голосовая заметка записывается реально либо честно помечается как локальный черновик без обещания расшифровки.
- AI-TEASE-1: teaser `Скоро ✨ · Хочу первым` пишет `FeatureInterest` и не вызывает внешние AI-сервисы.
- EMAIL-1: email fallback для клиента без мессенджера.
- POLISH: убрать пустышки, рассинхрон `за 2ч/за 1ч`, перезагрузки и некорректные labels.

## Уже выполнено в рамках этого прохода

- Усилен mobile `/api/mobile/blocks`: поддержка частичных временных блокировок `startTime/endTime`, корректный диапазон дат, отмена только пересекающихся сессий.
- Android API-модель `CreateBlockRequest` расширена `startTime/endTime`.
- Android invite request по умолчанию переведён на `channel = auto`, чтобы соответствовать smart-link и MAX-first CJM.
- Добавлен backend для `FeatureInterest` и mobile endpoint `/api/mobile/feature-interest`.
- Добавлен admin endpoint `/api/admin/feature-interest` для счётчиков интереса.
- Добавлены миграции `FeatureInterest` и audit-поля legal acceptance.
- Убран неявный legal accept при входе через `auth.ts`.
- Legal gate в web теперь проверяется до onboarding.
- Web/mobile legal acceptance пишут snapshot версии, типа документа и источника.
- Клиентская страница документа требует явный checkbox + кнопку; сервер action валидирует checkbox.
