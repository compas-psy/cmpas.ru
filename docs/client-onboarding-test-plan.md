# Client onboarding test plan

## Web Desktop

1. Открыть `/diary/clients`.
2. Нажать `Добавить`.
3. Создать нового тестового клиента.
4. Убедиться, что карточка остается на новом клиенте, а не переключается на клиента с последней старой сессией.
5. Создать первую запись.
6. Проверить, что появляется модалка первого сообщения клиенту.
7. Выбрать Telegram или MAX.
8. Отметить `Уведомление о записи` и документ.

## Web Mobile

1. Повторить сценарий на мобильной ширине.
2. Проверить, что открывается bottom-sheet.
3. Для неподключенного клиента проверить invite-link и нативный share.
4. Проверить, что readyText не содержит HTML-тегов.

## Telegram

1. Для подключенного клиента отправить сообщение через Telegram.
2. Проверить:
   - жирные выделения;
   - ссылки спрятаны за текстом;
   - нет превью ссылки ВКС;
   - нет лишнего тире перед договором.

## Документ клиента

1. Открыть ссылку документа из сообщения.
2. Убедиться, что страница читаемо отображается на мобильном.
3. Проверить, что факт принятия/открытия фиксируется в журнале документов клиента.

## Регрессия

Не трогать `/onboarding` и `/api/onboarding` — это онбординг психолога, не клиентский флоу.
